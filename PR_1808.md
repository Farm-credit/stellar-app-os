## Summary

Implements fractionalized impact-certificate minting for micro-benefactors (issue #1808): a new Soroban contract that lets non-corporate benefactors pool small contributions for a verified community agroforestry plot and receive fractional, NFT-style certificates proportional to their contribution.

### What changed

- **`contracts/impact-certificate-fractionalization/` (new crate)** — `Cargo.toml`, `src/lib.rs`, `src/test.rs`:
  - `register_plot` by a registered verifier with steward, payment token, share count, share price, deadline and plot metadata;
  - `contribute` escrows payment-token amounts, enforces micro-contribution bounds and a 100-benefactor cap, accumulates per-wallet contributions and flips the plot to `Funded` at the target (`total_shares * share_price`);
  - `mint_shares` mints one configurable `ShareCertificate` per non-refunded benefactor, releases the pooled funds to the steward and gives the last certificate the integer-division remainder so minted shares always sum to `total_shares`;
  - `refund` escape hatches for cancelled plots, expired open plots and funded plots left un-minted past a 7-day grace period — minted plots can never be refunded;
  - `transfer_shares` with partial transfers and automatic merging when the receiver already holds a certificate for the same plot;
  - views for `status`, funding progress in basis points, projected shares, refund eligibility and certificate lookup, so clients can render loading/funded/minted/refund states without failed transactions;
  - 7 typed contract events and 24 dedicated custom errors with clear auth, state and arithmetic boundaries.
- **`contracts/Cargo.toml`** — registers the new crate in the workspace.
- **`contracts/harvesta-errors/src/standard.rs`** — appends the new crate to the allocation table as index 56 (`0x390000-0x39FFFF`) without renumbering any existing namespace; adds registry tests for lookup and origin resolution. The new error enum uses literal discriminants with compile-time assertions against `global_code(56, local)`, following the existing `zk-location-verifier` pattern (`#[contracterror]` accepts only literals).
- **`docs/contracts/error-code-standard.md`** and **`docs/contracts/impact-certificate-fractionalization.md`** — allocation-table update and the new contract's workflow, roles, state machine, limits, error block and verification instructions.

### Compatibility

No existing contract, storage layout or error code was changed. The new crate only appends a namespace to the shared standard, so existing frontend error maps stay valid. It reuses the standard Soroban SEP-41 token client for payments and is deployable on testnet with the same WASM build as the other workspace contracts.
