## Summary

Implements non-transferable Soulbound impact badges for verified stewards in `contracts/nft-certificate` (issue #1815).

The checked-in `lib.rs` was badly corrupted by earlier automated fix scripts (duplicate `mint` definitions, duplicated/broken `merge` and `split` loops, stray statements, undefined variables and an unclosed delimiter) and did not compile at all. It has been reconstructed into a single coherent contract while preserving every previously intended entry point (issuer management, mint/batch mint, merge, split, trade with 5% royalty, protocol verification, pause/admin helpers).

### Soulbound implementation

- `Token` now carries a persistent `soulbound` flag; `NftError::TokenIsSoulbound = 7` is used by the shared error registry.
- `mint_soulbound` / `batch_mint_soulbound` issue badges already bound to the verified steward.
- `make_soulbound(authority, token_id)` irreversibly binds an existing certificate. Only the admin or the certificate's issuer may call it; a second call fails with `AlreadySoulbound` (309).
- `trade` rejects bound certificates with `TokenIsSoulbound` **before** any payment transfer or ownership change, so no funds move on a rejected trade.
- `merge` / `split` also reject bound certificates, closing the burn-and-remint loophole.
- `is_soulbound(token_id)` is a view helper for front-ends to display a "non-transferable impact badge" notice; `soulMint`, `soulBtch` and `soulbond` events let indexers and UIs observe the state.

All token storage was normalised to persistent `DataKey::Token(id)` (the old file mixed persistent and instance storage, which made `owner_of`, `original_planter_of` and `trade` read different records). The stale three-argument `mint` was removed in favour of the issuer-authorised version; unit and integration tests were updated accordingly.
