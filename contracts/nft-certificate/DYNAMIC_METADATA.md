# Dynamic certificate metadata and growth state

The NFT certificate contract tracks growth progress independently from the existing `Token` record. This preserves the serialized token shape and existing `get_token` result. New clients can use `get_growth_state(token_id)` to retrieve the growth stage, monotonic `update_sequence`, and current `metadata_uri`; unknown token IDs return `None`. Newly minted tokens begin at `Seeded`, sequence `0`, with no URI. `token_uri(token_id)` returns the latest supplied URI, or its historical built-in SVG data URI until the first update.

`update_growth(authority, token_id, update_sequence, stage, metadata_uri)` is authorized only for the certificate's original issuer or contract admin, and requires that authority's Soroban authorization. A successful update must use exactly the previous sequence plus one and move exactly one step through `Seeded → Planted → Sprout → Sapling → Mature`. No transition beyond `Mature` is allowed. This deliberately rejects user-asserted jumps/regressions instead of interpreting caller-supplied stage as proof. The designated issuer/admin remains responsible for accepting planting-verification evidence off-chain or through its trusted verification workflow before submitting each transition. URI values must be non-empty and at most 512 bytes; clients should use immutable/content-addressed references when practical.

Each accepted change emits a `growth` event keyed by token ID with old stage, new stage, sequence, and URI. The sequence prevents replay or out-of-order submissions. Dynamic URI updates do not alter ownership, carbon attributes, soulbound status, or the existing token ABI. The method is subject to the contract's global pause flag.
