## Summary

Implements the Planter Reputation Scoring Engine stored on-chain (issue #1812): a new Soroban contract that maintains a durable, auditable reputation ledger for both farmers and non-farmer community tree stewards from verified milestone outcomes.

### What changed

- **`contracts/planter-reputation/` (new crate)** — `Cargo.toml`, `src/lib.rs`, `src/test.rs`:
  - `register_steward` / `register_steward_for` create profiles for `Farmer` and `CommunitySteward` alike, starting at score 100 / tier Bronze, with self-service and admin (KYC import) paths;
  - `record_milestone` is verifier-gated and computes a score delta from configurable weights (`success_points + min(trees / divisor, max_tree_bonus)`, or `-failure_penalty`), clamps the score to `0..=max_score`, derives the tier and appends an immutable ledger entry with delta, tree count, resulting score and timestamp;
  - a permanent 32-byte milestone `reference` replay guard prevents the same milestone from ever inflating a score twice, across verifiers, stewards and penalties;
  - `apply_penalty` gives admins a bounded, replay-protected dispute/blacklist correction; `set_active` suspends stewards; `set_weights` validates and updates the scoring policy;
  - non-panicking views (`get_profile`, `get_score`, `get_tier`, `is_eligible`, `get_entries`, `get_entry`) let clients render empty, loading and ineligible states without failed transactions;
  - profiles, ledger entries and replay markers use persistent storage with the shared `contract-utils` storage policy; six typed events support indexers; 15 typed errors cover all auth, state and arithmetic boundaries.
- **`contracts/Cargo.toml` / `contracts/Cargo.lock`** — registers the new workspace crate.
- **`contracts/harvesta-errors/src/standard.rs`** — appends `planter-reputation` as allocation index 57 (`0x3A0000-0x3AFFFF`) without renumbering any existing namespace; adds lookup/origin tests. `docs/contracts/error-code-standard.md` documents the new row.
- **`docs/contracts/planter-reputation.md`** — roles, workflow, scoring formula, storage classes, error boundaries and verification commands.

### Compatibility

No existing contract, storage layout or error code was changed. The new crate only appends a namespace to the shared standard, so existing frontend error maps stay valid. It reuses the project's `harvesta-errors` standard and `contract-utils` storage policy and builds with the same Soroban 27 toolchain as the other contracts; it is deployable on testnet with the standard WASM build.

### Verification

- `cargo fmt -p planter-reputation -p harvesta-errors -- --check` → clean.
- `cargo test --offline -p planter-reputation -p harvesta-errors` → **32 passed / 0 failed** (19 new contract tests + 13 registry tests), covering both steward kinds, score/tier transitions, clamping, ledger ordering, replay and penalty guards, weights validation, auth boundaries and eligibility views.
- `cargo clippy --offline -p planter-reputation --all-targets --all-features --no-deps -- -D warnings -D clippy::all -D clippy::pedantic` → clean.
